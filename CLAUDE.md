# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

**recetas-frontend** is the public website of Asadorov, a non-profit atlas of Spanish cooking. It's a SvelteKit 3 app (Svelte 5, TypeScript strict) built with `@sveltejs/adapter-node`. It is the only public entry point: Caddy proxies to it, and it talks to the Go API over the internal Docker network (`../specs/stack.md` X4).

Before working on anything user-facing, read `../CLAUDE.md` (workspace rules, domain model, search semantics) and the relevant design README: mobile `../design/design_handoff_asadorov_mvp/README.md` below 860px, desktop `../design/design_handoff_asadorov_desktop/README.md` from 860px. Check `../specs/stack.md` before adding a library, and read the current stage file in `../specs/stages/frontend/` before starting work.

CI (`.github/workflows/ci.yml`) runs lint → actionlint (`pnpm lint:actions`, the digest-pinned image recetas-infra and recetas-backend use) → check → api:check → test → build, then the Playwright suite in 4 shards inside the official Playwright image (aggregated as the required "E2E Smoke" check). PRs and `main` run the tiered matrix; the full 9-project matrix runs nightly and via the workflow's manual `e2e-matrix: full` input. A separate `Lighthouse` job builds once and runs `lhci:mobile` and `lhci:desktop`, uploading `.lighthouseci/` as an artifact. On pushes to `main` (and `v*` tags) the workflow then pushes `ghcr.io/cosmofactory/recetas-frontend:sha-<7>` (plus `:vX.Y.Z`); no `:latest`. The image job exposes the `sha-<7>` tag as its `sha-tag` output, which `deploy-demo` deploys (see Deploy below). A change is done when `pnpm lint && pnpm check && pnpm test && pnpm build` pass.

Tests: unit tests are `*.spec.ts` (Node), component tests `*.svelte.spec.ts` (Vitest browser mode, Chromium), E2E `*.e2e.ts` (Playwright). Playwright projects cover mobile 390/360/430 and desktop 860/1280/1440 on Chromium, plus WebKit (iPhone, desktop 1440) and Firefox (1280). Tiered matrix (specs/stack.md F4): `chromium-mobile-390` and `chromium-desktop-1280` run every test; the other Chromium widths run only tests tagged `@layout` (result depends on the width: viewport geometry, wrapping/clipping, the 860px switch, sticky positions), and WebKit/Firefox only `@cross-browser` (engine behaviour: focus, history/scroll restore, view transitions, sticky, fonts, axe). Tag new E2E tests accordingly (`test('…', { tag: ['@layout'] }, …)`); a test that sets its own widths with `setViewportSize` (e.g. home-header's "the 860px switch") stays untagged, since the project width doesn't change its result; `E2E_MATRIX=full pnpm test:e2e` runs everything everywhere. Every E2E spec imports `test` (and `expect`, types) from `src/testutil/e2e-test.ts` (relative, e.g. `'../testutil/e2e-test'`), never `@playwright/test`: its `page` fixture fails a test on any CSP violation, and `e2e-test.spec.ts` enforces the import. A test that needs other runtime env vars (e.g. `MEDIA_BASE_URL`, `DATA_SOURCE=api`) starts its own `node build` with `startAppServer` (`src/testutil/app-server-e2e.ts`). `src/routes/E2E-COVERAGE.md` maps every FE-1 to FE-7 acceptance bullet to its tests; update it when you add or change an acceptance test. With `E2E_BASE_URL` set, the suite runs against that deployment (no local server); a test that needs the local build, mock-only setup or a specific `APP_ENV` calls `skipAgainstDeployment(why)` (`src/testutil/e2e-target.ts`).

**Nightly demo E2E (INF-2).** `.github/workflows/nightly-demo-e2e.yml` runs the full matrix (`E2E_MATRIX=full`, 4 shards, the same Playwright image) against `E2E_BASE_URL=https://demo.asadorov.es` every night at 04:43 UTC and on manual dispatch, once `DEPLOY_ENABLED` is `true`. It builds nothing, starts no server and uses no secrets; it fails fast when demo's `/readyz` isn't 200, and uploads `test-results/` on failure. `E2E_APP_ENV` stays unset, so `robots-noindex.e2e.ts` expects demo's noindex. Every E2E test must stay read-only and pass on demo's data (seeded from `content.design.json`, the mock bundle's source) behind Caddy (`encode zstd gzip`, no caching, Caddy's own `X-Robots-Tag` and security headers); anything else calls `skipAgainstDeployment(why)`.

**Deploy (`deploy-demo` job, INF-2).** On a push to `main`, once this repo's own repository variable `DEPLOY_ENABLED` is `true`, it runs in the GitHub environment `demo` (deployment branches: `main` only) with only the `SSH_HOST`, `SSH_USER`, `SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS` secrets. The key is restricted on the VM to recetas-infra's `ssh-gate.sh frontend demo`, which execs only `deploy-service.sh demo frontend sha-<7>`; the job sends exactly that with the image job's `sha-tag` output, pinning the host key (`StrictHostKeyChecking=yes`, `BatchMode=yes`). `deploy-service.sh` waits for health, rolls back to the previous tag and exits non-zero on a failed rollout, keeping the container logs in `/srv/recetas/demo/deploy.log` on the VM (the job log is public). Then the job smoke-tests `https://demo.asadorov.es/` and `/readyz` with bounded retries. Concurrency group `deploy-demo`: a running deploy is never cancelled, and the VM-side `flock` also queues it against the backend and infra deploys. Owner setup is in the README (Deploy). Rollback: re-run only the `Deploy Demo` job of an older run, never "Re-run all jobs" (that rebuilds and re-pushes the same `sha-` tag), or as the owner (as `deploy`) `/srv/recetas/scripts/deploy-service.sh demo frontend sha-<old>`.

## Rules

- **Svelte 5 runes only**: `$state`, `$derived`, `$props`, `$effect`. Never `export let`, `$:`, or stores for component state. Runes mode is forced in `vite.config.ts`.
- **Tokens are the only source of visual values.** Colours, type, spacing, radii and shadows come from `src/lib/styles/tokens.css`, which mirrors the design `tokens.css` byte for byte (never edit it; `pnpm tokens:check`). Never hard-code or round a value. The one exception is the WCAG AA overrides at the top of `layout.css` (stack.md X10 "Contrast overrides"): `--ink-2`, `--ink-3`, `--ink-eyebrow` and `--ink-placeholder` are nudged to pass 4.5:1 on every background they sit on, accent-coloured text uses `--accent-text`, and filled buttons use `--bg-button` / `--bg-button-hover` (never `--accent` / `--accent-hover`, which stay for borders and the map). App-level tokens the design file lacks (sheet geometry, content width, desktop padding/gap, `--hit-min`/`--hit-inset`, hover colours and shadows from the READMEs, `--radius-button-compact` from the prototype, `--focus-ring`) go in `src/lib/styles/layout.css`, loaded after tokens.css; it also holds the one shared `:focus-visible` ring, so components never style focus themselves. Those two files are the only place a colour literal may be written: `pnpm check:colors` (part of lint) fails on a hex colour or a colour function (`rgb()`, `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()`, `color-mix()`) in any other CSS, `.svelte` style/`style:`/SVG colour attribute or script string, and on a CSS named or system colour (`red`, `white`, `Canvas`, …; lists in `scripts/css-named-colours.ts` and `scripts/css-system-colours.ts`) in CSS values. `transparent`, `currentColor` and the CSS-wide keywords are allowed.
- **UI primitives** live in `src/lib/components/ui/` (`IconButton`, `Chip`/`ChipRow`, `SegmentedSwitch` (buttons, or links when options have an `href`), `LanguageButton`, `PrimaryButton`, `TextButton`); screens compose them and never restyle them. Icons come from `@lucide/svelte`, one import path per icon (`@lucide/svelte/icons/search`), mapped by name in `ui/icons.ts`. Controls grow their hit area to 44px with a `::before` at `inset: var(--hit-inset)` (Chip grows its border box; in a wrapping `ChipRow`, and the search suggestion chips, only by half the row gap vertically, the FE-3 exception), and `:hover` styles sit under `@media (hover: hover)`. Sizes: `TextButton` `small`/`medium` are responsive (both 12px below 860px; 12.5px / 13px from 860px), while `size="desktop"` on `Chip`/`ChipRow`/`FilterGroups` is a fixed desktop size for desktop-only containers. The `/:lang/_dev/ui` gallery shows them all under `vite dev` and answers 404 in any build.
- **Containers** (F6) are also in `src/lib/components/ui/`: `BottomSheet` (mobile region/dish sheet; controlled `state` `hidden|peek|expanded` + `onStateChange`, state logic in `#lib/ui/sheet.ts`), `OverlaySheet` (Filters; `open` + `onClose`), `StickyPanel` (desktop region panel) and the `Scrim` they use; stacking via `--z-sheet`/`--z-overlay` in layout.css. They take content as a `children` snippet and render it untouched. Screen frame contract: the home screen is a viewport-sized, positioned frame with `overflow: hidden`; the sheets are absolutely positioned inside it (each in a layer with `overflow: clip`, so focusing a control never scrolls it), and there is no body scroll lock. The sheet body owns scrolling: BottomSheet's content scrolls in a body below the handle, OverlaySheet scrolls itself (capped at the frame height), both with `overscroll-behavior: contain`. Content components (`RegionDetails`, `DishDetails`, `FilterGroups`) go in `src/lib/content/`, receive only data and callbacks, and never import a container (ESLint `no-restricted-imports` there); screens pick the container. Sheet keyboard and focus behaviour lives in one place, `sheetKeyboard` (`#lib/ui/sheet-keyboard.svelte.ts`), built on `#lib/ui/focus-trap.ts` (`trapFocus`, `rememberFocus`, `tabbableWithin`) and `#lib/ui/escape-layers.ts` (one document Escape listener; only the topmost shown layer closes, `menu` above `search` above `overlay` above `sheet`, and a `defaultPrevented` Escape is ignored): a sheet is inert while hidden, modal (focus trap, `aria-modal`) only when expanded/open, and focus returns to the opener once hidden unless the user has moved it elsewhere. `trapFocus(container, { initialFocus: 'container' })` (sheetKeyboard `initialFocus`) focuses the container itself (`tabindex="-1"`) instead of its first control, for a layer that moves focus in later; focus is inside the trap from the start, so Tab can't escape mid-transition. Every Escape-closable layer, including the search overlay, the language menu and any popover or dialog, registers through `pushEscapeLayer` with a `kind` (add kinds above `overlay` when they arrive), never with its own document keydown listener or native close handling. Under reduced motion a closing sheet fades out where it rests, then moves (`placeWhileFading`, `#lib/ui/fade-out.svelte.ts`).
- **Navigation** (FE-3): the root layout calls `pagePush()` (`#lib/ui/page-push.svelte.ts`, one `onNavigate`) and loads `#lib/styles/page-push.css`. Direction comes from route depth in one table, `ROUTE_DEPTH` in `#lib/ui/page-push.ts` (home and regions 0, dish 1, recipe 2; deeper = push, shallower = pop, anything else none; add new routes there). It runs a View Transition marked `<html data-page-push="push|pop|fade">`; there is no page push at ≥ 860px; without the API only a push animates, via `data-page-push-fallback` on `.app-shell`; a back/forward gesture the browser animates itself (`PopStateEvent.hasUAVisualTransition`, recorded by a capture-phase `popstate` listener) gets no page push. A newer navigation supersedes a page push whose transition hasn't captured yet: its update throws (transition skipped) and its `onNavigate` promise never resolves, because Kit would otherwise render that stale page over the newer one (a quick Back after a tap). `StickyTopBar` (mobile Variations/Recipe bar: back link, title and `--border-card` hairline past a `threshold`, window or `scrollContainer` scroll, passive listener) and `BackPill` (desktop back link, label from the caller) are in `src/lib/components/ui/`. Per-history-entry state (D-FE6-1) uses Kit's `snapshot` only through `entrySnapshot` (`#lib/ui/entry-snapshot.ts`, browser only) and `scrollSnapshot(id, scroller)` (`#lib/ui/scroll-snapshot.ts`; the mobile Popular list and the filter bar's `ChipRow`, exposed by its bindable `element`); each id must be unique among mounted components, so register in a single-instance screen component. `inAppBack(id, onOrigin?)` (`#lib/ui/in-app-back.ts`) is a back link's click handler: `history.back()` only when the entry was reached by a forward push (`pageDirection === 'push'`), else the href. The same per-entry record is the page's origin (`recordOrigin` in `#lib/ui/back-origin.ts`: the URL pushed from, `from` home or Variations, and its home tab; a push from Variations carries the Variations tab over), reported through `onOrigin` on record and on restore; never add a second origin mechanism.
- **Desktop primitives** (FE-3, global classes in `layout.css`): `.page-container` is the 1440px content cap (border-box, so it includes `--desktop-side-padding`, applied from 860px; no gap, screens set their own); a screen puts it on its own grid element. `.desktop-only` / `.mobile-only` are the one CSS breakpoint helper (`not all and (min-width: 860px)` / `(min-width: 860px)`: exact complements, so no fractional width falls between them; no range syntax, which Safari before 16.4 ignores): `media-queries.spec.ts` scans every shipped stylesheet and fails on any other width media query, on a `:hover` rule not under a plain `@media (hover: hover)` (a `not`, `or` or comma prelude doesn't count) and on a `<style>` element in component markup. `.hover-lift` is the shared desktop card hover (from 860px under `(hover: hover)`: 2px lift, `--shadow-card-hover`; under reduced motion no lift at all, only the shadow); `.visually-hidden` hides text from sight but not from assistive tech. `DesktopTopBar` (`ui/`, `.desktop-only`) is a full-width `<header>` whose row is a `.page-container`: logo link, `SegmentedSwitch size="desktop"`, spacer, a `search` snippet and the language button (visible upper-case code plus the localized label as visually hidden text) in a wrapper that anchors the `languageMenu` snippet; whether it is sticky is up to the screen.
- **Map** (FE-4): `src/lib/map/map-grid.json` is a byte copy of the design `map-grid.json` (D-FE4-1; `pnpm map-grid:sync` / `map-grid:check`, never edit it). `parseGrid` / `labelPosition` (`#lib/map/grid.ts`) are the pure layout; `#lib/map/region-map.ts` parses the bundled file once (`shapedRegions`, `ShapedRegion`). `RegionMap` (`src/lib/content/`) takes `{ regions, selectedKey?, hrefFor }` and draws only the regions passed, in that order. The map is the screen-reader region list: a `<ul role="list">` with one `<li>` per region holding its one link (`MapRegion`, `hrefFor(key)`, `aria-current` when selected, a first plain Space press activates like Enter); there is no separate hidden list. The cells are `aria-hidden`. A region's accessible name is its visible `mapLabel` chip plus the full name as visually hidden text when they differ (WCAG 2.5.3), never an `aria-label`. `tileColor` lands in a style attribute, so it is validated once at the server boundary by `withValidTileColor` (`#lib/server/region-colour.ts`, `#RRGGBB` only, used by `api-source.ts` per fetched list and detail and by `mock/bundle-mapping.ts`): a bad value is logged and becomes `null`, which the map draws as `--placeholder`. `layout.css` holds two map rules: the focus ring drawn on the region's label (the one documented exception to "components never style focus"; the region's cells aren't a rectangle), and forced colours (each cell keeps an outline, the selected region's cells are `Highlight`).
- **Home** (FE-4): `/:lang/` and `/:lang/regions/:regionKey` are pages of the `(home)` route group, whose `+layout.svelte` renders the whole screen (the home page only sets its `<title>`/description, `home-head.ts`), so navigating between them keeps the header and map mounted. The tab is in the URL (`#lib/ui/home-tab.ts`): `?tab=popular` is Popular, anything else Regional, and a region URL is always Regional. Tabs are links (`SegmentedSwitch` option `href` → `<a role="tab">`, `data-sveltekit-reset="false"`) to `tabHref(tab, lang)`, always the bare home, so switching closes any region: a click is the link's own navigation (a new history entry); arrow keys call `onChange`, which `goto`s with `replace: true, reset: false`. Both tabpanels are always in the page (the unselected one `hidden` and empty). There is ONE `RegionMap` instance, in `RegionalTab` (`src/lib/components/home/`), styled for both layouts by CSS, so crossing 860px keeps it; never render a second map per layout. On mobile its frame is a size container, so the map's width follows the height left (landscape). SSR renders `MobileHeader` (`.mobile-only`) and `DesktopTopBar` together, so only the mobile header's switch gets the `panelId`s (`tabOptions(lang, true)` in `home-header.ts`), and each header's language menu has its own id; ids must stay unique in the HTML. Both use `LanguageButton` (`ui/`, `size="mobile|desktop"`). The mobile `<h1>` is the logo, the desktop one the "How Spain really cooks" title (`AboutBlock`). Region details (FE-4 PR 3): `RegionDetails` (`src/lib/content/`, `{ region, dishes, recipeHref, mediaBaseUrl }`, rows from `regionVariations` in `#lib/content/region-variations.ts`, dish order; the region name is an `<h2>`, chips are plain labels, each row is one link to its recipe) renders twice in `RegionalTab`, and both containers are in the SSR HTML (CSS hides one): mobile `RegionSheet` (`home/`, a `.mobile-only` `BottomSheet` named by the region) and desktop `StickyPanel` (named by the region) in the right column. The sheet state comes from the URL (`urlSheetState` in `#lib/ui/sheet.ts`, shared through `UrlSheet` with the FE-5 dish sheet): a region URL is peek, the handle's expanded is local (reset on every navigation, no history entry), `/:lang/` and desktop widths are hidden; it keeps the last region's content while it slides out. Scrim and Escape `goto('/:lang/', { reset: false })` as a new entry, so Back reopens the region; the map box has `data-sveltekit-reset="false"`, so activating a region keeps focus on its link and closing returns focus there (Kit 3 has no `keepFocus`; never use the default `reset` for these navigations). WebKit doesn't focus a link on tap, so the opener is also recorded explicitly (`sheetOpener` in `#lib/ui/sheet-opener.ts`, passed as `opener` to the sheet); a cold load records nothing and focuses nothing. On desktop `/:lang/` shows `DEFAULT_DESKTOP_REGION_KEY` (Andalucía) in the panel without touching the URL, and the map marks it `aria-current` only once hydrated (`MediaQuery(desktopQuery)`; the server renders the mobile selection). Without JavaScript it still looks selected on desktop: `RegionMap` `defaultKey` sets `data-default` on that region while the URL has none, styled as selected only from 860px. The handle's expanded state also resets when the sheet goes inactive (desktop widths), and `BottomSheet`/`StickyPanel` take a `contentKey` that scrolls them back to the top when it changes (`scrollToTopOn`, `#lib/ui/scroll-reset.svelte.ts`). The layout wraps both tabpanels in the page's one `<main>`; the mobile header and the desktop top bar stay outside it. The region page only sets its head: "Asadorov · {name}" (`regionTitle`) and the region description. `home-a11y.e2e.ts` runs axe (`@axe-core/playwright`, WCAG 2.0–2.2 A/AA) on the home screens in `chromium-mobile-390` and `chromium-desktop-1280`.
- **Home Popular** (FE-5): filters are repeated `f` URL params with locale-independent ids (`#lib/popular/filters.ts`, one `FILTER_TABLE`; `toggleFilterHref`/`clearFiltersHref` drop every other param), navigated with `replace: true, reset: false`. `PopularTab` renders `PopularSidebar` (desktop), the `ResultCount`, `DishResults` and the mobile `DishSheet` (`?dish=<key>`, same URL-sheet rules as the region sheet; desktop ignores it); `PopularFilters` holds the mobile `FilterBar` and the in-memory `FiltersSheet` (closed on desktop widths). `FilterGroups` and `DishDetails` live in `src/lib/content/`; `FilterGroups`, `ChipRow` and `Chip` take `size="desktop"` for the sidebar. Desktop (FE-5 PR 3): the panel's `.page-container` is a `220px minmax(0,1fr)` grid of the sticky sidebar (a `<section>` named by its "Filters" `<h3>`, the same `FilterGroups`, and a "Clear all" `TextButton` that is `inactive` (`aria-disabled`, 40% opacity, still focusable) while nothing is active) and the results column (count, then the `auto-fill minmax(250px, 1fr)` card grid). The window scrolls on desktop, so nothing around the cards or the sidebar may set `overflow` (the sticky sidebar itself is capped at the window and scrolls, like `StickyPanel`, so Tab never lands below the viewport); on mobile the list scrolls in its own container. There is ONE `DishCard` per dish, restyled by CSS from 860px (with `.hover-lift`); its href comes from `dishCardHref` (`#lib/popular/card-href.ts`): the server renders the Variations page `/:lang/dishes/:key` (works without JS on both layouts, crawlable), and once hydrated mobile switches to the dish sheet URL (`MediaQuery(desktopQuery, true)` in `DishResults`, swapped live across 860px). Only the mobile list has `data-sveltekit-reset="false"`; a desktop card navigation keeps Kit's default scroll and focus reset.
- **Recipe page** (FE-6 PR 3): `+page.svelte` renders `StickyTopBar` (threshold 280, back = `inAppBack('recipe-back')`, href the Variations page) and, inside `{#key dishKey/regionKey}`, `RecipeBody` (`src/lib/components/recipe/`), which owns the servings `$state` and renders `RecipeHeader` (the Time/Serves strip goes in as its `strip` snippet, so on desktop it sits in the hero's text column) and the ingredients/method body; `IngredientList` and `MethodSteps` own their ticks. Kit reuses the page component on a Recipe → Recipe navigation, so per-recipe in-memory state must live under that key. Logic: `formatRecipeTime` (`#lib/recipe/time.ts`), `SERVINGS_MIN`/`MAX`, `clampServings`, `ingredientQuantity` (`#lib/recipe/servings.ts`). Rows are `<button aria-pressed>`; the stepper announces through a visually hidden `aria-live="polite"` span that stays empty until the first change.
- **Desktop Variations and Recipe** (FE-6 PR 4): one page per route for both layouts; CSS switches them, so state (servings, ticks) survives crossing 860px. Each page renders `DishPagesTopBar` (`src/lib/components/dish/`, the home's `DesktopTopBar`, not sticky, switch value = `originTab(origin)`) outside its `<main>`, then in `main.page-container` the `StickyTopBar` in a `.mobile-only` `display: contents` slot (so it still sticks to the window) and the `BackPill` (`data-testid="back-pill"`) in a `.desktop-only` wrapper. Pill label and href come from `variationsBackPill`/`recipeBackPill` (`#lib/components/dish/back-pill.ts`): the direct-load target on the server and without an origin, else the origin's label and URL, and a click goes `history.back()`. The header, cards, hero and body are real `display: grid` elements from 860px; the ingredients card (`data-testid="recipe-ingredients-card"`) is `position: sticky; top: 24px` against the window, so no ancestor may set `overflow` and the body grid has no bottom padding. Forward navigation keeps Kit's default scroll reset; Back restores Kit's saved offset.
- **Search logic** (FE-7 PR 1): pure modules in `src/lib/search/`. `normalize` (`normalize.ts`) is the one search normalisation (lowercase, `ё→е`, strip combining marks except the breve on `и`, so `й ≠ и`, D-FE7-1); never normalise search text anywhere else. `buildIndex({ regions, dishes }, locale)` (`search-index.ts`) turns the `[lang=lang]` layout's lists into entries `{ group, title, subtitle, dishKey?, regionKey?, tileColor?, haystack }`; the group order lives only in `SEARCH_GROUPS` (dish → variation → region). The haystack holds the normalised title, subtitle and Spanish `nameEs`, plus a dish's variation names (local and Spanish) and a variation's description. `search(index, query)` (`search.ts`) trims the query, substring-matches the haystack and returns non-empty `{ group, entries }` in index (catalog) order, capped at `MAX_RESULTS_PER_GROUP`.
- **Search overlay** (FE-7 PR 2, mobile): `SearchOverlay` (`src/lib/components/search/`, `{ open, index, onClose, onSelect, opener? }`, controlled like `OverlaySheet`) is a full-screen `position: fixed` dialog at `--z-search` (above everything, including the Filters sheet), escape-layer kind `search`, modal while open via `sheetKeyboard` with `initialFocus: 'container'`: the input gets focus only once the dialog's own enter transitions finish (`afterOwnTransitions`, `#lib/ui/after-transitions.ts`; 250ms fade `--dur-search-fade`, 350ms slide `--dur-search`; fade only under reduced motion).
