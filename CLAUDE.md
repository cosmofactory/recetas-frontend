# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

**recetas-frontend** is the public website of Asadorov, a non-profit atlas of Spanish cooking. It's a SvelteKit 3 app (Svelte 5, TypeScript strict) built with `@sveltejs/adapter-node`. It is the only public entry point: Caddy proxies to it, and it talks to the Go API over the internal Docker network (`../specs/stack.md` X4).

Before working on anything user-facing, read `../CLAUDE.md` (workspace rules, domain model, search semantics) and the relevant design README: mobile `../design/design_handoff_asadorov_mvp/README.md` below 860px, desktop `../design/design_handoff_asadorov_desktop/README.md` from 860px. Check `../specs/stack.md` before adding a library, and read the current stage file in `../specs/stages/frontend/` before starting work.

CI (`.github/workflows/ci.yml`) runs lint → check → api:check → test → build, then the Playwright smoke on every project. On pushes to `main` (and `v*` tags) it then pushes `ghcr.io/cosmofactory/recetas-frontend:sha-<7>` (plus `:vX.Y.Z`); no `:latest`. The deploy trigger arrives with INF-2. A change is done when `pnpm lint && pnpm check && pnpm test && pnpm build` pass.

Tests: unit tests are `*.spec.ts` (Node), component tests `*.svelte.spec.ts` (Vitest browser mode, Chromium), E2E `*.e2e.ts` (Playwright). Playwright projects cover mobile 390/360/430 and desktop 860/1280/1440 on Chromium, plus WebKit (iPhone, desktop 1440) and Firefox (1280).

## Rules

- **Svelte 5 runes only**: `$state`, `$derived`, `$props`, `$effect`. Never `export let`, `$:`, or stores for component state. Runes mode is forced in `vite.config.ts`.
- **Tokens are the only source of visual values.** Colours, type, spacing, radii and shadows come from `src/lib/styles/tokens.css`, which mirrors the design `tokens.css` byte for byte (never edit it; `pnpm tokens:check`). Never hard-code or round a value. The one exception is the WCAG AA overrides at the top of `layout.css` (stack.md X10 "Contrast overrides"): `--ink-2`, `--ink-3` and `--ink-eyebrow` are nudged to pass 4.5:1, accent-coloured text uses `--accent-text`, and filled buttons use `--bg-button` / `--bg-button-hover` (never `--accent` / `--accent-hover`, which stay for borders and the map). App-level tokens the design file lacks (sheet geometry, content width, desktop padding/gap, `--hit-min`/`--hit-inset`, hover colours and shadows from the READMEs, `--radius-button-compact` from the prototype, `--focus-ring`) go in `src/lib/styles/layout.css`, loaded after tokens.css; it also holds the one shared `:focus-visible` ring, so components never style focus themselves. Those two files are the only place a colour literal may be written: `pnpm check:colors` (part of lint) fails on a hex colour or a colour function (`rgb()`, `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()`, `color-mix()`) in any other CSS, `.svelte` style/`style:`/SVG colour attribute or script string, and on a CSS named or system colour (`red`, `white`, `Canvas`, …; lists in `scripts/css-named-colours.ts` and `scripts/css-system-colours.ts`) in CSS values. `transparent`, `currentColor` and the CSS-wide keywords are allowed.
- **UI primitives** live in `src/lib/components/ui/` (`IconButton`, `Chip`/`ChipRow`, `SegmentedSwitch` (buttons, or links when options have an `href`), `LanguageButton`, `PrimaryButton`, `TextButton`); screens compose them and never restyle them. Icons come from `@lucide/svelte`, one import path per icon (`@lucide/svelte/icons/search`), mapped by name in `ui/icons.ts`. Controls grow their hit area to 44px with a `::before` at `inset: var(--hit-inset)` (Chip grows its border box; in a wrapping `ChipRow` only by half the row gap vertically, the FE-3 exception), and `:hover` styles sit under `@media (hover: hover)`. Sizes: `TextButton` `small`/`medium` are responsive (both 12px below 860px; 12.5px / 13px from 860px), while `size="desktop"` on `Chip`/`ChipRow`/`FilterGroups` is a fixed desktop size for desktop-only containers. The `/:lang/_dev/ui` gallery shows them all under `vite dev` and answers 404 in any build.
- **Containers** (F6) are also in `src/lib/components/ui/`: `BottomSheet` (mobile region/dish sheet; controlled `state` `hidden|peek|expanded` + `onStateChange`, state logic in `#lib/ui/sheet.ts`), `OverlaySheet` (Filters; `open` + `onClose`), `StickyPanel` (desktop region panel) and the `Scrim` they use; stacking via `--z-sheet`/`--z-overlay` in layout.css. They take content as a `children` snippet and render it untouched. Screen frame contract: the home screen is a viewport-sized, positioned frame with `overflow: hidden`; the sheets are absolutely positioned inside it (each in a layer with `overflow: clip`, so focusing a control never scrolls it), and there is no body scroll lock. The sheet body owns scrolling: BottomSheet's content scrolls in a body below the handle, OverlaySheet scrolls itself (capped at the frame height), both with `overscroll-behavior: contain`. Content components (`RegionDetails`, `DishDetails`, `FilterGroups`) go in `src/lib/content/`, receive only data and callbacks, and never import a container (ESLint `no-restricted-imports` there); screens pick the container. Sheet keyboard and focus behaviour lives in one place, `sheetKeyboard` (`#lib/ui/sheet-keyboard.svelte.ts`), built on `#lib/ui/focus-trap.ts` (`trapFocus`, `rememberFocus`, `tabbableWithin`) and `#lib/ui/escape-layers.ts` (one document Escape listener; only the topmost shown layer closes, overlay above sheet, and a `defaultPrevented` Escape is ignored): a sheet is inert while hidden, modal (focus trap, `aria-modal`) only when expanded/open, and focus returns to the opener once hidden unless the user has moved it elsewhere. Every Escape-closable layer, including the future search overlay, language menu and any popover or dialog, registers through `pushEscapeLayer` with a `kind` (add kinds above `overlay` when they arrive), never with its own document keydown listener or native close handling. Under reduced motion a closing sheet fades out where it rests, then moves (`placeWhileFading`, `#lib/ui/fade-out.svelte.ts`).
- **Navigation** (FE-3): the root layout calls `pagePush()` (`#lib/ui/page-push.svelte.ts`, one `onNavigate`) and loads `#lib/styles/page-push.css`. Direction comes from route depth in one table, `ROUTE_DEPTH` in `#lib/ui/page-push.ts` (home and regions 0, dish 1, recipe 2; deeper = push, shallower = pop, anything else none; add new routes there). It runs a View Transition marked `<html data-page-push="push|pop|fade">`; there is no page push at ≥ 860px; without the API only a push animates, via `data-page-push-fallback` on `.app-shell`; a back/forward gesture the browser animates itself (`PopStateEvent.hasUAVisualTransition`, recorded by a capture-phase `popstate` listener) gets no page push. A newer navigation supersedes a page push whose transition hasn't captured yet: its update throws (transition skipped) and its `onNavigate` promise never resolves, because Kit would otherwise render that stale page over the newer one (a quick Back after a tap). `StickyTopBar` (mobile Variations/Recipe bar: back link, title and `--border-card` hairline past a `threshold`, window or `scrollContainer` scroll, passive listener) and `BackPill` (desktop back link, label from the caller) are in `src/lib/components/ui/`. Per-history-entry state (D-FE6-1) uses Kit's `snapshot` only through `entrySnapshot` (`#lib/ui/entry-snapshot.ts`, browser only) and `scrollSnapshot(id, scroller)` (`#lib/ui/scroll-snapshot.ts`; the mobile Popular list and the filter bar's `ChipRow`, exposed by its bindable `element`); each id must be unique among mounted components, so register in a single-instance screen component. `inAppBack(id)` (`#lib/ui/in-app-back.ts`) is a back link's click handler: `history.back()` only when the entry was reached by a forward push (`pageDirection === 'push'`), else the href.
- **Desktop primitives** (FE-3, global classes in `layout.css`): `.page-container` is the 1440px content cap (border-box, so it includes `--desktop-side-padding`, applied from 860px; no gap, screens set their own); a screen puts it on its own grid element. `.desktop-only` / `.mobile-only` are the one CSS breakpoint helper (`not all and (min-width: 860px)` / `(min-width: 860px)`: exact complements, so no fractional width falls between them; no range syntax, which Safari before 16.4 ignores): `media-queries.spec.ts` scans every shipped stylesheet and fails on any other width media query, on a `:hover` rule not under a plain `@media (hover: hover)` (a `not`, `or` or comma prelude doesn't count) and on a `<style>` element in component markup. `.hover-lift` is the shared desktop card hover (from 860px under `(hover: hover)`: 2px lift, `--shadow-card-hover`; under reduced motion no lift at all, only the shadow); `.visually-hidden` hides text from sight but not from assistive tech. `DesktopTopBar` (`ui/`, `.desktop-only`) is a full-width `<header>` whose row is a `.page-container`: logo link, `SegmentedSwitch size="desktop"`, spacer, a `search` snippet and the language button (visible upper-case code plus the localized label as visually hidden text) in a wrapper that anchors the `languageMenu` snippet; whether it is sticky is up to the screen.
- **Map** (FE-4): `src/lib/map/map-grid.json` is a byte copy of the design `map-grid.json` (D-FE4-1; `pnpm map-grid:sync` / `map-grid:check`, never edit it). `parseGrid` / `labelPosition` (`#lib/map/grid.ts`) are the pure layout; `#lib/map/region-map.ts` parses the bundled file once (`shapedRegions`, `ShapedRegion`). `RegionMap` (`src/lib/content/`) takes `{ regions, selectedKey?, hrefFor }` and draws only the regions passed, in that order. The map is the screen-reader region list: a `<ul role="list">` with one `<li>` per region holding its one link (`MapRegion`, `hrefFor(key)`, `aria-current` when selected, a first plain Space press activates like Enter); there is no separate hidden list. The cells are `aria-hidden`. A region's accessible name is its visible `mapLabel` chip plus the full name as visually hidden text when they differ (WCAG 2.5.3), never an `aria-label`. `tileColor` lands in a style attribute, so it is validated once at the server boundary by `withValidTileColor` (`#lib/server/region-colour.ts`, `#RRGGBB` only, used by `api-source.ts` per fetched list and detail and by `mock/bundle-mapping.ts`): a bad value is logged and becomes `null`, which the map draws as `--placeholder`. `layout.css` holds two map rules: the focus ring drawn on the region's label (the one documented exception to "components never style focus"; the region's cells aren't a rectangle), and forced colours (each cell keeps an outline, the selected region's cells are `Highlight`).
- **Home** (FE-4): `/:lang/` and `/:lang/regions/:regionKey` are pages of the `(home)` route group, whose `+layout.svelte` renders the whole screen (the home page only sets its `<title>`/description, `home-head.ts`), so navigating between them keeps the header and map mounted. The tab is in the URL (`#lib/ui/home-tab.ts`): `?tab=popular` is Popular, anything else Regional, and a region URL is always Regional. Tabs are links (`SegmentedSwitch` option `href` → `<a role="tab">`, `data-sveltekit-reset="false"`) to `tabHref(tab, lang)`, always the bare home, so switching closes any region: a click is the link's own navigation (a new history entry); arrow keys call `onChange`, which `goto`s with `replace: true, reset: false`. Both tabpanels are always in the page (the unselected one `hidden` and empty). There is ONE `RegionMap` instance, in `RegionalTab` (`src/lib/components/home/`), styled for both layouts by CSS, so crossing 860px keeps it; never render a second map per layout. On mobile its frame is a size container, so the map's width follows the height left (landscape). SSR renders `MobileHeader` (`.mobile-only`) and `DesktopTopBar` together, so only the mobile header's switch gets the `panelId`s (`tabOptions(lang, true)` in `home-header.ts`) and only one header may get the language menu's `controls` (FE-7); ids must stay unique in the HTML. Both use `LanguageButton` (`ui/`, `size="mobile|desktop"`). The mobile `<h1>` is the logo, the desktop one the "How Spain really cooks" title (`AboutBlock`). Region details (FE-4 PR 3): `RegionDetails` (`src/lib/content/`, `{ region, dishes, recipeHref, mediaBaseUrl }`, rows from `regionVariations` in `#lib/content/region-variations.ts`, dish order; the region name is an `<h2>`, chips are plain labels, each row is one link to its recipe) renders twice in `RegionalTab`, and both containers are in the SSR HTML (CSS hides one): mobile `RegionSheet` (`home/`, a `.mobile-only` `BottomSheet` named by the region) and desktop `StickyPanel` (named by the region) in the right column. The sheet state comes from the URL (`urlSheetState` in `#lib/ui/sheet.ts`, shared through `UrlSheet` with the FE-5 dish sheet): a region URL is peek, the handle's expanded is local (reset on every navigation, no history entry), `/:lang/` and desktop widths are hidden; it keeps the last region's content while it slides out. Scrim and Escape `goto('/:lang/', { reset: false })` as a new entry, so Back reopens the region; the map box has `data-sveltekit-reset="false"`, so activating a region keeps focus on its link and closing returns focus there (Kit 3 has no `keepFocus`; never use the default `reset` for these navigations). WebKit doesn't focus a link on tap, so the opener is also recorded explicitly (`sheetOpener` in `#lib/ui/sheet-opener.ts`, passed as `opener` to the sheet); a cold load records nothing and focuses nothing. On desktop `/:lang/` shows `DEFAULT_DESKTOP_REGION_KEY` (Andalucía) in the panel without touching the URL, and the map marks it `aria-current` only once hydrated (`MediaQuery(desktopQuery)`; the server renders the mobile selection). Without JavaScript it still looks selected on desktop: `RegionMap` `defaultKey` sets `data-default` on that region while the URL has none, styled as selected only from 860px. The handle's expanded state also resets when the sheet goes inactive (desktop widths), and `BottomSheet`/`StickyPanel` take a `contentKey` that scrolls them back to the top when it changes (`scrollToTopOn`, `#lib/ui/scroll-reset.svelte.ts`). The layout wraps both tabpanels in the page's one `<main>`; the mobile header and the desktop top bar stay outside it. The region page only sets its head: "Asadorov · {name}" (`regionTitle`) and the region description. `home-a11y.e2e.ts` runs axe (`@axe-core/playwright`, WCAG 2.0–2.2 A/AA) on the home screens in `chromium-mobile-390` and `chromium-desktop-1280`.
- **Home Popular** (FE-5): filters are repeated `f` URL params with locale-independent ids (`#lib/popular/filters.ts`, one `FILTER_TABLE`; `toggleFilterHref`/`clearFiltersHref` drop every other param), navigated with `replace: true, reset: false`. `PopularTab` renders `PopularSidebar` (desktop), the `ResultCount`, `DishResults` and the mobile `DishSheet` (`?dish=<key>`, same URL-sheet rules as the region sheet; desktop ignores it); `PopularFilters` holds the mobile `FilterBar` and the in-memory `FiltersSheet` (closed on desktop widths). `FilterGroups` and `DishDetails` live in `src/lib/content/`; `FilterGroups`, `ChipRow` and `Chip` take `size="desktop"` for the sidebar. Desktop (FE-5 PR 3): the panel's `.page-container` is a `220px minmax(0,1fr)` grid of the sticky sidebar (a `<section>` named by its "Filters" `<h3>`, the same `FilterGroups`, and a "Clear all" `TextButton` that is `inactive` (`aria-disabled`, 40% opacity, still focusable) while nothing is active) and the results column (count, then the `auto-fill minmax(250px, 1fr)` card grid). The window scrolls on desktop, so nothing around the cards or the sidebar may set `overflow` (the sticky sidebar itself is capped at the window and scrolls, like `StickyPanel`, so Tab never lands below the viewport); on mobile the list scrolls in its own container. There is ONE `DishCard` per dish, restyled by CSS from 860px (with `.hover-lift`); its href comes from `dishCardHref` (`#lib/popular/card-href.ts`): the server renders the Variations page `/:lang/dishes/:key` (works without JS on both layouts, crawlable), and once hydrated mobile switches to the dish sheet URL (`MediaQuery(desktopQuery, true)` in `DishResults`, swapped live across 860px). Only the mobile list has `data-sveltekit-reset="false"`; a desktop card navigation keeps Kit's default scroll and focus reset.
- **Recipe page** (FE-6 PR 3): `+page.svelte` renders `StickyTopBar` (threshold 280, back = `inAppBack('recipe-back')`, href the Variations page), `RecipeHeader` and, inside `{#key dishKey/regionKey}`, `RecipeBody` (`src/lib/components/recipe/`), which owns the servings `$state`; `IngredientList` and `MethodSteps` own their ticks. Kit reuses the page component on a Recipe → Recipe navigation, so per-recipe in-memory state must live under that key. Logic: `formatRecipeTime` (`#lib/recipe/time.ts`), `SERVINGS_MIN`/`MAX`, `clampServings`, `ingredientQuantity` (`#lib/recipe/servings.ts`). Rows are `<button aria-pressed>`; the stepper announces through a visually hidden `aria-live="polite"` span that stays empty until the first change.
- **Breakpoint and motion in script:** branch on `desktopQuery` from `#lib/ui/breakpoints.ts` (860px, `DESKTOP_MIN_WIDTH_PX`), never a copied number; for reduced motion use `prefersReducedMotion` and `motionFor()` from `#lib/ui/motion.svelte.ts` (slides become fades).
- **No hard-coded user-visible strings.** Every string is a Paraglide message, `m.*()` from `#lib/paraglide/messages.js`. Messages come from `../design/design_handoff_asadorov_desktop/strings.json` via `pnpm strings:import`; copy the design lacks (e.g. error pages) goes in `src/lib/i18n/extra-strings.json`, never straight into `messages/` (generated, committed) or markup. Keys are the strings.json path joined with `_` (`home.filterLabels["With pork"]` → `home_filterLabels_withPork`); plurals take `{ count }` and include the number (a new plural array is listed in `PLURAL_KEYS`, `scripts/import-strings.ts`). `pnpm check:strings` fails on literal text and literal `alt`/`aria-label`/`placeholder`/`title`; only the logo "Asadorov" is allowed.
- **i18n routing (F7, X6):** every page lives under `src/routes/[lang=lang]/` (matcher in `src/params.ts`). The URL path alone decides the language: `hooks.server.ts` takes it from the path (en for paths without a locale) and sets `<html lang>`. Every internal link uses `localizedHref(path, lang)` from `#lib/i18n/localized-href.ts`; a raw `href="/…"` fails `pnpm check:strings`. Numbers and units use `formatNumber`/`unitLabel` (`#lib/i18n/format.ts`), never string building.
- **Env (Kit 3):** runtime variables are declared in `src/env.ts` (`defineEnvVars`) and read from `$app/env/private` / `$app/env/public`; `$env/dynamic/*` is deprecated and only sees declared variables. `PUBLIC_ORIGIN` (e.g. `https://demo.asadorov.es`) is required outside `vite dev`: canonical and hreflang URLs use it, never the request Host. adapter-node 6 has no `ORIGIN` variable. `DATA_SOURCE` and `BACKEND_API_BASE_URL`: see Data source below.
- **Cookies and storage (X6):** the only cookie is `lang`, set server-side by `/set-lang` (FE-1). No `document.cookie`, `localStorage`, `sessionStorage` or `indexedDB`; ESLint enforces this. No browser analytics or telemetry.
- **Responsive (F6):** keep content components separate from layout containers; state lives in the URL; no hard-coded phone pixel widths; branch on input capability (`hover`, `pointer`) rather than width where it's about interaction. Breakpoint 860px, content max-width 1440px.
- **Data loading is server-only** (FE-2, X4). Loaders in `+page.server.ts` / `+layout.server.ts` call `catalog()` from `#lib/server/catalog.ts` (one process-wide `CatalogSource`, so the list cache is shared) and wrap every call in `orHttpError` (`#lib/server/load-errors.ts`): unknown key → 404, backend down → 503, both localised by `+error.svelte`. The `[lang=lang]` layout provides the `regions` and `dishes` lists; detail pages load their own region, dish or recipe. Types come from `src/lib/api/schema.d.ts`, generated from the vendored `src/lib/api/openapi.yaml` (never edit either by hand; `pnpm api:sync`). ESLint forbids `openapi-fetch` and global `fetch` outside `src/lib/server/`; server routes use `event.fetch`, except `/readyz`, which uses the global fetch (via `checkBackendReady`) because `event.fetch` re-wraps the request and its timeout signal can be garbage-collected (`timeout-under-gc.spec.ts`). Pass a timeout as `fetch(request, { signal })`, never inside `new Request(…, { signal })`, for the same reason. The browser never calls the Go API.
- **Data source:** `DATA_SOURCE=api` (default) reads the Go API at `BACKEND_API_BASE_URL` (internal origin, e.g. `http://backend:8080`; required outside `vite dev`, which defaults to `http://localhost:8080`). `DATA_SOURCE=mock` serves the vendored backend import bundle `src/lib/server/mock/content.bundle.json` (a copy of `recetas-backend/testdata/content.design.json`), for local dev and tests; Playwright runs with it, so E2E needs no backend. `src/env.ts` decides whether `BACKEND_API_BASE_URL` is required from the raw `process.env.DATA_SOURCE` (a schema can't see another variable's parsed value); under `vite dev` a `DATA_SOURCE` set only in `.env` isn't seen there, which only means the dev default URL is filled in. `/healthz` is liveness only; `/readyz` is 200 only when the backend `/healthz` answers, and 503 when no backend is configured (`BACKEND_API_BASE_URL` unset, e.g. in mock mode).
- Self-hosted fonts only; no request may go to a third-party origin. The one exception is photos from the media origin, `MEDIA_BASE_URL` (CloudFront, stack.md X3; optional, `public: true` in `src/env.ts`, https with an optional path). The API returns a key prefix per role (`thumb`/`card`/`hero`); `imageSet` in `#lib/media.ts` builds the AVIF/WebP/JPEG `srcset`s and rejects any prefix that isn't slug segments. Render photos with `#lib/components/Photo.svelte`, passing `data.mediaBaseUrl` from the `[lang=lang]` layout and a `sizes`. The design gives fixed heights: pass them as `height` (and `radius`) props, CSS lengths or token vars; without them the caller sizes the box. `<Photo>` fills it and crops with `object-fit: cover`. Set `priority` on the above-the-fold hero (eager, `fetchpriority="high"`); everything else loads lazily. With no prefix or no `MEDIA_BASE_URL` it draws the striped `--placeholder`; a bad prefix is drawn as the placeholder and logged on the server only.
- **Observability (FE-2, stack.md B7):** server-side OpenTelemetry only; no browser telemetry or client SDK (X6), and `@opentelemetry/*` may only be imported from `src/lib/server/` and `src/instrumentation.server.ts` (`telemetry/server-only.spec.ts`). Kit's `tracing: { server: true }` (in `vite.config.ts`) creates the request, handle and load spans; `src/instrumentation.server.ts`, which adapter-node loads before the app, registers the provider (OTLP/HTTP protobuf to Logfire, batched) only when `LOGFIRE_TOKEN` is set, and flushes it on adapter-node's `sveltekit:shutdown`. Settings are parsed in one place, `telemetryConfig` (`#lib/server/telemetry/config.ts`); `src/env.ts` declares the variables and runs the same validation. `/healthz` and `/readyz` are never traced, and an incoming `traceparent`'s sampled flag never decides what is recorded (the sampler treats a remote parent as none). The SDK's own `diag` reports at WARN and above go to the logger with the token and any `Authorization` value redacted (`telemetry/diag-logger.ts`). API calls are CLIENT spans named by the OpenAPI path (`GET /v1/dishes/{dishKey}`) that send `traceparent` to the Go API (`#lib/server/api-tracing.ts`, an openapi-fetch middleware above the retry, so a retried call is one span; a 404 is not an error, any other 4xx or a 5xx is). `@opentelemetry/api` is the one runtime `dependency`: Kit keeps it external so the app and the instrumentation share one global provider; every other OTel package is a bundled devDependency.
- **Server logs:** use `log.info` / `log.error` from `#lib/server/log.ts` (JSON lines like the Go API's slog, with `trace_id`/`span_id` inside a span), never `console.*`. Shared components can't import `$lib/server`; they call `reportError` from `#lib/report-error.ts`, which `hooks.server.ts` points at the logger in `init`. Pass the loader's `event` to `orHttpError(pending, event)` so a 503 is logged once per request, not once per loader. Unknown (unexpected) errors are logged by `handleError` in `hooks.server.ts` with the stack, route id and trace ids; it returns nothing, so the client only ever sees Kit's generic 500 body.
